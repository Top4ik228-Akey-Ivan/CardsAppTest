1. Строгий режим (`"use strict"`) — это специальный режим работы JavaScript, который делает некоторые правила языка более строгими и помогает находить ошибки. Сейчас при использовании современных модулей (`import/export`) строгий режим и так включен.
2. `var`, `let` и `const` используются для создания переменных

   `var` имеет область видимости функции и значение может быть переназначено, можно обратиться до объявления, но значение будет undefined

   `let` имеет область видимости блока `{}` и его значение можно изменить.

   `const` нельзя переназначить другой ссылкой. Однако содержимое объекта или массива, объявленного через `const`, изменять можно

   `const` применяется — по умолчанию, `let` — для счетчиков и меняющихся состояний, `var` — почти никогда, считается устаревшим
3. `==` `!=` сравнивает значения с приведением типов, а `===` `!==` сравнивает и значение, и тип.
   
   `'01' == 1` → **`true`**, потому что строка `"01"` при таком сравнении приводится к числу `1`

   `'01' === 1` → **`false`**, потому что один операнд — строка, а другой — число.
   
   `null === undefined` → **`false`**, потому что это разные типы и разные значения
   
   `null == undefined` → **`true`**. Это специальное правило нестрогого сравнения: `null` и `undefined` равны только друг другу.
   ```
   null > 0 → false 
   null == 0 → false
   null >= 0 → true
   ```
   При сравнении через `>`, `<`, `>=`, `<=` `null` приводится к числу `0`. Поэтому `null >= 0` — `true`. Но при `==` действует отдельное правило, и `null` не равен `0`.
    ```
   undefined > 0 → false
   undefined < 0 → false
   undefined == 0  → false
   ```
   При числовом сравнении `undefined` превращается в `NaN`, а сравнение с `NaN` всегда дает `false`. С `0` через `==` он тоже не равен.

5. Callback
  ```
    function confirmAction(question, onConfirm, onCancel) {
      const answer = prompt(`${question} (да/нет)`);

      if (answer?.toLowerCase() === "да") {
        onConfirm();
      } else {
        onCancel();
      }
    }

    confirmAction(
  ```

6. `this` — это ссылка на объект, в контексте которого сейчас вызывается функция.
   Потеря `this`:
  ```
  const user = {
    name: "Ivan",
    sayHello() {
      console.log(this.name);
    }
  };

  const hello = user.sayHello;
  hello(); // undefined
  ```
  Мы сохранили функцию отдельно, поэтому она больше не вызывается как метод `user`.
  Исправить можно с помощью `bind`:
  ```
  const hello = user.sayHello.bind(user);
  hello(); // Ivan
   ```
   Исправить можно с помощью `() =>`:
   ```
  setTimeout(() => user.sayHello(), 1000);
   ```
  Стрелочная функция берет this из внешнего контекста (где user существует)

7. `setTimeout` позволяет выполнить функцию один раз через определенное время

   `setInterval` позволяет выполнять функцию через определенный промежуток времени снова и снова

   Отменяются они соответственно: `clearTimeout(timer);` `clearInterval(interval);`

   Разница между `setInterval` и рекурсивным `setTimeout` в том, что при `setInterval` следующий запуск планируется независимо от того, закончился ли предыдущий вызов.
   
   С рекурсивным `setTimeout` следующий запуск можно запланировать только после выполнения текущего
8. TypeScript — это язык, основанный на JavaScript, который добавляет статическую типизацию. Главное отличие в том, что в TypeScript можно заранее указать типы данных. TypeScript нужен в первую очередь для того, чтобы находить ошибки раньше, делать код понятнее и удобнее при работе с большими проектами.
9. Типы
- `string`  — строка
- `number`  — число
- `boolean`  — булево значение
- `null` — отсутствие значения;
- `undefined` — значение не определено;
- `object` — объект;
- `array` — массив, например `number[]`;
- `tuple` — кортеж с фиксированными типами и порядком;
- `any` — фактически отключает проверку типа;
- `unknown` — неизвестный тип, который безопаснее `any`;
- `void` — обычно используется для функций, которые ничего не возвращают;
- `never` — значение, которое никогда не возникает, например функция, которая всегда выбрасывает ошибку.

10. `Generics` позволяют писать код, который работает с разными типами, но при этом сохраняет информацию о конкретном типе. 
  ```
    function getFirst<T>(items: T[]): T {
      return items[0];
    }

    const number = getFirst([1, 2, 3]);       // 3 — number
    const name = getFirst(["Ivan", "Alex"]);  // "Ivan" — string
  ```
   Здесь `T` — это тип, который будет определен при вызове функции.
  ```
    interface Response<T> {
      data: T;
      success: boolean;
    }

    const response: Response<string> = {
      data: "Hello",
      success: true
    };
  ```
   Одна и та же структура `Response` может использоваться для разных типов данных.

11. Оба способа позволяют описывать типы объектов

`interface` можно расширять:
  ```
    interface User {
      name: string;
    }

    interface Admin extends User {
      isAdmin: boolean;
    }
  ```
`type` удобен тем, что позволяет описывать не только объекты, но и объединения, пересечения и другие типы:
  ```
    type Status = "loading" | "success" | "error";

    type User = {
      name: string;
    } & {
      age: number;
    };
  ```
12. Для отдельных свойств используется `?` `age?: number;`

	Если нужно сделать все свойства необязательными, используется встроенный тип `Partial` `type PartialUser = Partial<User>;`

13. `Omit` позволяет создать новый тип на основе существующего, исключив из него определенные свойства. Это удобно, например, когда объект из базы данных содержит `id`, но при создании нового пользователя `id` передавать не нужно.
14. Да. В TypeScript можно сделать несколько вариантов сигнатуры одной функции, а затем написать одну общую реализацию.

  ```
    function format(value: string): string;
    function format(value: number): string;

    function format(value: string | number): string {
      return String(value);
    }

    format("hello");
    format(123);
  ```
