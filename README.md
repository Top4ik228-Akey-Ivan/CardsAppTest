# Wordly — SPA для изучения английских слов
 
Тестовое задание на позицию **Middle Frontend Developer**.
Одностраничное приложение на **React + Redux + TypeScript**: авторизация, карточки для изучения слов и форма редактирования профиля.
 
**Уровень реализации: Полный ✅** (авторизация + карточки за авторизацией + профиль со связанными полями)

## Иерархия компонентов
 
Приложение построено по компонентной иерархии, приближённой к классическому layout-паттерну:
 
```
Page
├── Header      (навигация, данные о пользователе — через пропсы)
├── Body        (полезная нагрузка страницы)
│   ├── CardList → Card       (карточки слов)
│   └── EditView → Field      (форма профиля)
└── Footer      (контакты — через пропсы)
```
 
`Header` и `Footer` ничего не знают о сторе — все данные для отображения (имя пользователя, email поддержки) прокидываются им через пропсы из `Page`.

## Как работают редиректы
 
Логика авторизации построена декларативно, на двух route-guard компонентах, каждый из которых сам подписан на `state.auth.isAuthenticated` через `useSelector` и реагирует на его изменение — без ручных вызовов `navigate()` из формы логина. Это исключает гонки состояний между обновлением стора и переходом по роуту.
 
- **`PrivateRoute`** — оборачивает `/cards` и `/profile`. Если пользователь не авторизован, редиректит на `/login`, сохраняя исходный путь в `location.state.from` — чтобы после успешного входа вернуть пользователя туда, откуда его увели.
- **`PublicRoute`** — оборачивает `/login`. Если пользователь уже авторизован (или только что вошёл в систему), редиректит его на `location.state.from`, а если такого пути нет (авторизовался, зайдя на `/login` напрямую) — на `/cards`.
- Несуществующие пути (`*`) редиректят на `/`.
Таким образом, сценарий «зашёл на `/cards` без авторизации → залогинился → автоматически вернулся на `/cards`» работает без единой лишней строчки навигации в компоненте формы.
 
## Карточки слов
 
- Данные о словах лежат локально в коде и отдаются через **RTK Query** с кастомным `baseQuery`, имитирующим сетевой запрос (с задержкой ~600 мс). Такой подход был выбран осознанно вместо обращения к внешнему бесплатному mock-сервису (например, mockapi.io) — сторонние бесплатные API не дают гарантий доступности и иногда попросту не отвечают, что не должно ломать демо-версию проекта.
- При этом публичный интерфейс данных остаётся таким же, как при реальном REST-запросе: `useGetCardsQuery()` возвращает `data`, `isLoading`, `isError` — компоненты (`CardsPage`, `CardList`) ничего не знают о том, что источник данных локальный, и не потребуют изменений, если в будущем понадобится вернуться на настоящий бэкенд (нужно будет заменить только `baseQuery` в `cardsApi.ts`).
- `CardList` принимает массив карточек через пропсы и рендерит `Card` для каждой.
- Каждая карточка получает случайный мотивирующий заголовок (например, *Word of the Day*) из предустановленного набора.
- По клику на кнопку **LEARN MORE** карточка переворачивается (CSS 3D-flip) и показывает перевод; кнопка **НАЗАД** возвращает карточку на лицевую сторону.
- Состояния загрузки и ошибки сети обрабатываются отдельно (`isLoading` / `isError`) с выводом уведомления.
## Форма профиля
 
- 21 поле, покрывающие все обязательные по заданию типы: строка, число, текст (textarea), дата, выпадающий список, группа чекбоксов, группа радио-кнопок.
- **Связанные поля**: при выборе статуса занятости «Студент» поле «Компания» скрывается, а в поле «Должность» подставляется предустановленное значение и оно блокируется для редактирования; при статусе «В поиске работы» оба поля скрываются.
- Значения формы синхронизированы с Redux-стором (`profileSlice`) через единый экшен `updateProfile`.
- **Сохранение**: при каждом обновлении профиля состояние дополнительно пишется в `localStorage`. При следующем визите на `/profile` (или перезагрузке страницы) данные подтягиваются из `localStorage` ещё на этапе инициализации стора — форма всегда открывается с последними сохранёнными значениями, без лишних запросов и «мигания» пустых полей.
- Дата хранится в сериализуемом виде (`YYYY-MM-DD`), конвертация в объект для `DatePicker` и обратно происходит на границе компонента `Field`, не затрагивая стор.
## Сообщения и обратная связь
 
- **Ошибка входа** — при неверном логине/пароле под формой появляется `Alert` с понятным текстом («Неправильный логин или пароль»), кнопка входа показывает состояние загрузки.
- **Ошибка загрузки карточек** — обработка на случай сбоя источника данных предусмотрена (`isError` из RTK Query выводит `Alert` с предложением обновить страницу), хотя при текущих локальных данных этот сценарий не воспроизводится намеренно.
- **Успешное сохранение профиля** — при сохранении формы показывается всплывающее уведомление `message.success('Профиль успешно сохранен')`.
